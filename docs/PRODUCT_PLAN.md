# 金融コストウォッチ — プロダクト方針

## 位置づけ

hanbaijo.comを、暗号資産だけの比較サイトから「金融商品の見えない取引コストを実測・整理するデータメディア」へ拡張する。
広告報酬によるおすすめ順位ではなく、自社計測データと再現可能な計算方法を信頼の中心に置く。

## 優先順位

1. 暗号資産の既存計測を維持し、欠測率と履歴品質を改善する。
2. FXの主要通貨ペアで実測基盤を追加する。正式なAPIと再掲載条件を確認できた提供元だけを採用する。
3. 同一金額・同一保有期間で比較できるコスト計算機を追加する。
4. CFDへ広げ、スプレッドに価格調整額・金利調整額を加える。
5. 株式・先物は市場価格の差ではなく、手数料、信用金利、為替コスト、注文機能を比較する。

## データ原則

- `observed`（実測値）、`published`（公称値）、`estimated`（試算値）を混在させない。
- 取得失敗を他社データや直前値で補完しない。
- 取得時刻、出典URL、計算式のバージョンを保存する。
- 画面スクレイピングは、提供者が自動取得と再掲載を明示的に許可した場合だけ採用する。
- 広告契約の有無や報酬額を、実測値と機械的な並び順に反映しない。

## コンテンツモデル

大量生成はページ数ではなく、固有データを持つ検索意図の数として管理する。各インデックス対象ページには、次のいずれかを必須とする。

- 固有の時系列または集計データ
- 金額・期間を指定した固有の試算
- 一次情報へのリンクと確認日
- 独自の比較軸または計測方法

最初の90日は約120ページを上限とし、ハブ15、比較30、データ50、税制・制度15、注文・ツール10を目安にする。
検索流入・回遊・広告クリックの実測を見て、需要が確認できた型だけを300〜500ページへ増やす。

## 公開ゲート

- ASP審査中は、本番サイト、ドメイン設定、既存記事、公開リンクを変更しない。
- 新デザインと新カテゴリは作業ブランチで検証する。
- 公開前に数値表現、広告表示、免責、リンク属性、モバイル表示、構造化データを再確認する。
- セキュリティ設定の変更は、変更内容と影響範囲を提示したうえで承認後に実施する。
